📗 Tavo → PiuPiu v1 · 对齐实测样本

把 Tavo tavo_spec:"lorebook" / tavo_spec_version:2 转成 PiuPiu / 酒馆世界书（character_book）格式。 输出默认采用 keys / secondary_keys / insertion_order / enabled / extensions 结构，字段顺序稳定， 可被《PiuPiu → Rikkahub》按原样读回。

① 输入

未选择文件
自动识别方向：含 tavo_spec，或条目里出现 key / keysecondary / disable / display_index 等 Tavo 字段 → 执行转换；条目里出现 keys / secondary_keys / insertion_order / enabled （PiuPiu / 酒馆 character_book）→ 走「规范化 + 校验」。

② 转换选项

高级设置（默认即可用）
Tavo 顶层没有 name / description，这里由你补齐，只影响 PiuPiu 世界书本身，不影响条目内容。
字符串模式：position 只能是 before_char / after_char（角色卡 v2 规范）， 真正的 7 种位置信息交给 extensions.position 数字保存。
数字模式：position 直接写 0～6，与酒馆世界书导出一致， 传给《PiuPiu → Rikkahub》时能完整还原「在深度」等位置。
role 会写入 extensions.role（v2 规范位置）；开启下面的「兼容增强字段」时也会同时写条目顶层 role。
合并模式适合目标端不支持次级关键词时；清空模式适合你只想保留常驻条目正文。
Rikkahub 的 priority 来自这里，所以顺序要保住。若 Tavo 里 order 全同，报告会给「一键改用顺序编号重转」。
条目的 scanDepth 会原样写进 extensions.scan_depth（为 null 时保持 null，表示跟随世界书）。
